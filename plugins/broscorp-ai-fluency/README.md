# broscorp-ai-fluency

Плагін для Claude Code з одним скілом — **`ai-fluency-audit`**. Він читає *вашу локальну* історію
Claude Code і видає персональний відгук за моделлю 4D (Delegation · Description · Discernment ·
Diligence): **частота кожної з 24 поведінок** (скільки разів за період вона проявилась, без оцінок 1–10), патерни
з прикладами, три поради з готовими шаблонами промптів і порівняння з минулим разом. Критерії — з внутрішнього гайда Broscorp та Framework for AI Fluency v1.1.

## Для співробітника

Встановлення (один раз):

```
/plugin marketplace add Broscorp-net/ai-fluency-audit
/plugin install broscorp-ai-fluency@broscorp-tools
```

Запуск — або словами («оціни, як я працюю зі ШІ»), або командою:

```
/broscorp-ai-fluency:ai-fluency-audit
/broscorp-ai-fluency:ai-fluency-audit 60      ← за 60 днів
```

Скіл спершу покаже список ваших проєктів і **спитає, що виключити** (наприклад, клієнтські).
Без вашої відповіді нічого не читається.

Потрібен **Python 3.9+** (python.org); пакетів встановлювати не треба.

### Працюєте на кількох комп'ютерах

Плагін ставиться окремо на кожному комп'ютері тією самою командою встановлення. Якщо адміністратор роздав його
автоматично (розділ «Для адміністратора»), нічого робити не треба.

Історія аудитів, за якою рахується динаміка, лежить на тому комп'ютері, де ви запускали скіл:
`~/.claude/ai-fluency/`. Щоб на іншому комп'ютері динаміка не починалася з нуля, винесіть цю теку в папку, яку ви
й так синхронізуєте (OneDrive, Dropbox, Google Drive), і вкажіть її змінною середовища `AI_FLUENCY_HOME`
на кожному комп'ютері.

Windows (PowerShell, один раз; потім перезапустіть Claude):

```
setx AI_FLUENCY_HOME "C:\Users\<імʼя>\OneDrive\ai-fluency"
```

macOS / Linux (додайте в `~/.zshrc` або `~/.bashrc`):

```
export AI_FLUENCY_HOME="$HOME/OneDrive/ai-fluency"
```

Теку скрипт створить сам. Якщо історія вже є в `~/.claude/ai-fluency/`, скопіюйте її вміст у нову теку.
Перевірити, що вийшло, можна після аудиту: шлях у рядку `HTML-звіт → …` має вести у вашу синхронізовану теку.

Хмарне сховище при цьому лишається **вашим особистим**: компанія результатів не отримує. Не запускайте аудит
на двох комп'ютерах одночасно: служба синхронізації може створити конфліктну копію `history.json`.

Саму історію чатів Claude Code скіл читає з того комп'ютера, на якому його запущено, і чатів з іншого не бачить.
Їх можна додати вручну: `collect --add "<файл .jsonl>"` (див. «Історія з інших інструментів» нижче).

## Приватність — що відбувається з даними

| Питання | Відповідь |
|---|---|
| Що читається | `~/.claude/projects/*/*.jsonl`: лише тексти ваших промптів, текст відповідей ШІ та **назви** викликаних інструментів |
| Що НЕ читається | Вміст файлів, виводи команд, «думки» моделі, субагенти |
| Секрети | Ключі, токени, паролі, email автоматично маскуються (`[REDACTED:…]`) до того, як текст потрапить у вибірку |
| Куди йдуть дані | Нікуди окрім поточної сесії Claude Code, яка й формує відгук. Скрипт не має мережевого коду (це перевіряє тест) |
| Історія з інших інструментів | За бажанням: скажіть скілу шлях до експорту ChatGPT, claude.ai чи Gemini — він додасть ці діалоги до вибірки (`collect --add "<шлях до файлу>"`). Сам скіл таких файлів не шукає |
| Що зберігається | Локально `~/.claude/ai-fluency/history.json`: частоти поведінки (скільки діалогів і проєктів), короткі висновки й числа збору (кількість сесій, проєктів і діалогів, медіанна довжина промпту, частка коротких промптів, перервані дії, замасковані фрагменти). **Без текстів промптів.** У висновках можуть бути назви ваших проєктів («діалог про впалий білд у проєкті genius») |
| HTML-звіт | Локальний файл у `~/.claude/ai-fluency/reports/`: частоти поведінки зі шкалами, патерни, поради з шаблонами промптів, динаміка, історія аудитів і згорнутий блок зі статистикою збору. Відкривається у браузері напряму, без вебсервера |
| Хто бачить результат | Лише ви. Компанія результатів не отримує |

## Для адміністратора

### Автоматична роздача всім співробітникам

У керованих налаштуваннях Claude Code (managed settings):

```json
{
  "extraKnownMarketplaces": {
    "broscorp-tools": {
      "source": { "source": "github", "repo": "Broscorp-net/ai-fluency-audit" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": {
    "broscorp-ai-fluency@broscorp-tools": true
  }
}
```

Розташування файлу `managed-settings.json`:

| ОС | Шлях |
|---|---|
| Windows | `C:\Program Files\ClaudeCode\managed-settings.json` |
| macOS | `/Library/Application Support/ClaudeCode/managed-settings.json` |
| Linux / WSL | `/etc/claude-code/managed-settings.json` |

Нюанси з документації Claude Code:
- За замовчуванням на машині діє лише **одне** джерело керованих налаштувань
  (server-managed → MDM → файл). Якщо вже використовуєте одне з них, додавайте ключі саме туди
  або виставте `managedSourcesBehavior: "merge"`.
- Альтернатива без прав адміністратора ОС: ті самі два ключі в `.claude/settings.json` репозиторію
  компанії (діє після того, як співробітник довірить папку).
- **Приватний репозиторій:** Claude Code не має власного git-токена, використовує звичайні
  git-облікові дані співробітника (SSH або `gh auth login` + `gh auth setup-git`).
  Для автооновлення у фоні `GITHUB_TOKEN` сам по собі не діє — лише через credential helper.
- **Доступ до репозиторію.** Він приватний: усі співробітники мають мати право читання (базові права організації
  чи команда з доступом Read), інакше `/plugin install` не спрацює. Це треба налаштувати в GitHub, звідси це не видно.
- **Щоб плагін був на будь-якому комп'ютері співробітника.** Файл `managed-settings.json` діє лише на машині, де його
  розгорнуто. Server-managed налаштування (консоль адміністратора claude.ai, найвищий пріоритет у списку вище)
  не залежать від конкретного комп'ютера. Чи доступні вони у вашому плані й як їх увімкнути, перевірте в консолі:
  для цієї організації я цього не перевіряв.
- Плагіни **недоступні в хмарних і WSL-сесіях**. Робота в Claude Desktop (вкладка Code) за документацією
  має підхоплювати керовані плагіни так само, але прямо це не підтверджено — перевірте на тестовій машині.

### Перед роздачею

1. `claude plugin validate ./plugins/broscorp-ai-fluency --strict` і `claude plugin validate .` (маркетплейс).
2. Локальна перевірка: `/plugin marketplace add ./шлях/до/репозиторію`, `/plugin install broscorp-ai-fluency@broscorp-tools`,
   потім запустити скіл на своїй історії.
3. Прочитати розділ про безпеку плагінів у документації Claude Code: плагін запускає скрипт на машинах співробітників.
   Скрипт ([`fluency.py`](skills/ai-fluency-audit/scripts/fluency.py)) невеликий і читається за 10 хвилин:
   лише стандартна бібліотека, без мережі, пише тільки у `~/.claude/ai-fluency/`.

### Оновлення

Змінили код чи рубрику → підніміть `version` у `plugin.json` **і** в `.claude-plugin/marketplace.json`
(у корені репозиторію) — без цього співробітники не отримають оновлення.
